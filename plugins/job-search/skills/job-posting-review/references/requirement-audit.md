# Requirement audit

Build one ledger per role before scoring. Read the whole posting, sentence by sentence, including the summary, duties, tools, pay notes, and application questions.

Each ledger row holds the exact posting wording, its source section, its type, the evidence grade, the evidence source, and any claim limit.

## Row types

| Type | Use for | Scored |
|---|---|---|
| Required | Items under requirements, qualifications, "must", or "you have", and unlabeled qualification lists | Yes |
| Preferred | Items marked preferred, nice to have, a plus, or bonus | Yes |
| Duty | The first six listed duties. With section headings, take them in turn from each section | Yes |
| Extra duty | Duties after the first six, and tools or domains named inside any duty. A scored duty stays scored | No, but use them for claim limits |
| Condition | Pay, location, travel, hours, deadlines, and other terms | No, send them to validation or pay conditions |

## Splitting rows

- Split "and" lists and "including" lists of named tools or products. A named sub-item is its own row. A list of general skills in one bullet stays one row, graded on its weakest item.
- Give an "or" list one row, graded on the user's best alternative.
- Give sub-aspects of one domain one row. "Insurance operations, claims administration, and workflows" is one domain.
- Merge repeated items into one row.
- Put personal traits and generic soft skills, such as "team player" or "organized", in one row. Concrete skills, such as presenting to executives, get their own rows.

## Evidence grades

Compare the task and the subject. For a tool, the task is the verb and the subject is the tool.

| Grade | Credit | Meaning |
|---|---|---|
| Direct | 1 | A project or role record shows the same task on the same subject |
| Partial | 0.5 | A record shows the same task on a different subject, or the same subject at a lesser depth; or the item appears only in a skill inventory, a supporting source, or one of the user's resumes |
| None | 0 | Neither, or the records exclude it |
| Unverified | Not scored | A yes-or-no fact the records don't hold; send it to validation |

Before grading None, search the routed records, supporting sources, and resumes for the term and its synonyms. When the grade is still in doubt, use the lower one.

## Miss patterns

Check each pattern before scoring:

| Pattern | Rule | Example |
|---|---|---|
| Bundled requirements | Apply the splitting rules. | "Microsoft 365, including Teams, SharePoint, Power Platform, and Copilot" is four rows. |
| Parent-skill credit | Credit in one tool never covers a sibling tool. Components of a parent product earn Partial at most for the parent. | Power Automate use does not cover Copilot, and earns Partial for Power Platform. |
| Absent evidence | A required item with no record is unmet. Never call it thin or light. | Required Copilot with no recorded use is None. |
| Inventory-only evidence | A skill list or passing mention without project evidence is Partial at most. | SharePoint named only in a skills inventory. |
| Depth mismatch | Compare the verb: used, configured, administered, owned, or led. Apply recorded limits. | SharePoint use, when the records exclude administration. |
| Experience arithmetic | Calculate months from dates, for the exact kind of experience asked for. Count only roles whose records show that work as a main duty. Count overlapping roles once, and part-time roles at half. Report the shortfall. | 4 years 8 months as a business analyst against 5+. |
| Unverified credentials | Never assume a license, clearance, or citizenship. Mark it Unverified. | A required driver's license that the records don't mention. |
| Duties-only items | Give tools and domains named only in duties an Extra duty row. | Azure DevOps, vendor management, or API configuration named in a duty. |
| Conditional pay | Find conditions attached to any part of the range, and mark whether the user meets them. | The top of the range is reserved for telecom experience. |
| Claim limits | Record what the user must not claim, including recorded restrictions. | Domains and tools with no evidence. |

Grade a years requirement Direct at 100% or more of the required months, Partial at 80-99%, and None below that.

## Equivalent-experience degree rows

A degree row may allow equivalent experience, such as "or equivalent work experience". When the user lacks the degree or holds it in another field, and the posting's experience row for that work grades Direct, ask the user whether the clause should satisfy the degree row. Put this in the grouped question before analysis.

- Yes: grade the row Direct, cite the user's answer as the evidence source, and leave it out of `Main risk` and the unmet list. Add a claim limit: never state a degree or field the user does not hold.
- No, or no answer: grade the row Partial, and list the degree field under evidence to confirm.

Ask for each posting. An answer covers only that posting unless the user's records state a standing answer.

## Finish the audit

Confirm that every tool, credential, domain, number, and condition in the posting has a ledger row. A missing row means the score isn't ready.

If a required item with no record may simply be unrecorded, list it under evidence to confirm. If the user adds evidence, regrade the row and rescore.
