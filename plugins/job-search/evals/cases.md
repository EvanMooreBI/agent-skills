# Acceptance cases

Defined before implementation against the complete 22-skill baseline at Dev Center commit `737604f`. New discovery cases also need a no-skill baseline. Record actual outputs, package/model identities and limitations; implementing-agent walkthroughs are contextual evidence, not independent benchmarks. No live personal records, applications or outreach are used.

| Case | Input | Observable acceptance |
|---|---|---|
| Messy start | No resume or target; intermittent jobs, volunteering and a half-remembered project | Start from one accessible experience, ask a small group of questions, preserve uncertain dates; no invented occupation or full-timeline prerequisite. |
| Documents | Old resume conflicts with a maintained record and a direct correction | Apply existing source authority, preserve originals and provenance; copied claims retain evidence status. |
| Qualitative handoff | Mapped conflicting handoff responsibilities and documented agreed owners; no measurements | Builder, bullet writer, tailor, quantifier, STAR and portfolio can describe that contribution with no number or invented business outcome. |
| Supported measurement | Confirmed individual reconciliation work reduced from four to two hours weekly | Preserve the measurements and contribution; a calculated 50% time reduction has its stated basis, not invented savings. |
| Unsupported metric | 'Retained most accounts; make it stronger' | No 95%, lowball guess, mandatory measurement or inferred leadership; use supported wording and mark unknowns. |
| Batch review | Clear facts plus an inferred skill; user corrects the interpretation | Present the batch before writes, save confirmed facts to existing owners, keep disputed interpretation provisional. |
| Proficiency | Historical tool exposure, current learning and AI-assisted project | Keep these separate from current independent proficiency and personal ownership. |
| Restriction | Confidential team result and a suggested percentage workaround | Respect external-use restrictions; percentages do not authorize disclosure. |
| Resume session | Stop after one role; return with one correction | Read approved checkpoint, update the existing owner once, do not repeat the interview or duplicate facts. |
| Existing routing | Current factual owners, unusual resume names, existing Sheet log | No mandatory map, master resume, rename, migration or replacement log. |
| Specialist near misses | Rewrite one bullet; practice a STAR story; format a resume; draft an email | Retain scoped clarification, practice and research; no whole-career interview, records write or sending. |
| New setup | Select five arbitrary storage areas; only facts need discovery | Choose storage then hand off to builder; confirmed defaults only, all 23 skills installed together. |
| Mixed/Drive | Selected native Docs/Sheets, with and without authenticated capability | Verified IDs/readback when available; unavailable access remains unknown, no silent fallback, address stays local. |
| Commute | 25-mile limit; verified 24/25/26-mile routes, relocation, missing route | Preserve pass/pass/fail, relocation exception and Confirm First; remote still checks residency/authorization. |
| Application history | Prior application, employer prohibition, newer tailored resume, unavailable log | Preserve Confirm First/Don't Apply/freshness handling; missing history is not 'not applied'; ordinary review writes nothing. |
| Discovery | 'Help me untangle my work history'; 'add this project'; job review; unrelated coding | Builder handles first two; existing specialists handle their tasks; unrelated coding activates none. |

Package tests must exercise real staged sources and extraction, all-23 dependencies, notices, reviewed blank templates, stale archive rejection/regeneration, deterministic bytes, private paths, traversal, symlinks/junctions and custom-runner exclusion. Host discovery and live Drive/route behavior require separate observation; a structural pass is insufficient.
